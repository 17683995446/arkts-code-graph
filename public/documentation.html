📊 流程图

代码分析流程

完整的代码分析流程包括：代码输入、语法解析、语义分析、图谱构建、分析处理和结果输出六个主要阶段。 

flowchart TD
    Start([🚀 开始]) --> Input[📥 代码输入]
    Input --> Parse[📝 AST 解析]
    Parse --> Lex{词法/语法正确?}
    Lex -->|否| Error[❌ 错误处理]
    Error --> Report[📋 生成错误报告]
    Report --> End([🔚 结束])
    Lex -->|是| Semantic[🧠 语义分析]
    Semantic --> Extract[🔍 信息提取]
    Extract --> Types{类型识别}
    Types -->|Class| C1[标记为类]
    Types -->|Function| C2[标记为函数]
    Types -->|Interface| C3[标记为接口]
    Types -->|Enum| C4[标记为枚举]
    C1 & C2 & C3 & C4 --> Relations[🔗 关系分析]
    Relations --> Deps[📊 依赖关系]
    Deps --> Graph[🕸️ 构建图谱]
    Graph --> Optimize[⚡ 性能优化]
    Optimize --> Query[🔍 查询处理]
    Query --> Output[📤 结果输出]
    Output --> End

并发处理流程

flowchart TD
    Start([🚀 启动]) --> Init[⚙️ 初始化资源]
    Init --> Pool[🏊 创建对象池]
    Pool --> Workers[👥 启动工作池]
    Workers --> Queue[📋 创建任务队列]
    Queue --> Dispatch{分发任务}
    Dispatch -->|任务1| W1[Worker 1]
    Dispatch -->|任务2| W2[Worker 2]
    Dispatch -->|任务3| W3[Worker N]
    W1 --> Result1[📊 结果1]
    W2 --> Result2[📊 结果2]
    W3 --> Result3[📊 结果3]
    Result1 & Result2 & Result3 --> Merge[🔗 结果合并]
    Merge --> Validate[✅ 验证完整性]
    Validate -->|通过| Success[🎉 成功]
    Validate -->|失败| Retry[🔄 重试]
    Retry --> Dispatch
    Success --> Cleanup[🧹 资源清理]
    Cleanup --> End([🔚 结束])

⏱️ 时序图

代码分析时序

展示从用户发起分析请求到获取结果的完整时序过程，涉及客户端、Web服务器、核心引擎和数据库多个组件。 

sequenceDiagram
    participant Client as 👤 客户端
    participant Web as 🌐 Web服务器
    participant Engine as 🔥 核心引擎
    participant Parser as 📝 解析器
    participant Graph as 🕸️ 图数据库

    Client->>Web: POST /api/analyze
    Web->>Engine: 提交分析任务
    Engine->>Parser: 解析代码
    Parser-->>Engine: 返回 AST
    Engine->>Engine: 语义分析
    Engine->>Graph: 创建节点
    Graph-->>Engine: 节点 ID
    Engine->>Graph: 创建关系
    Graph-->>Engine: 关系 ID
    Engine->>Graph: 构建索引
    Graph-->>Engine: 索引完成
    Engine-->>Web: 分析结果
    Web-->>Client: 返回 JSON

容错处理时序

sequenceDiagram
    participant Client as 👤 客户端
    participant Service as 🔗 服务
    participant Retry as 🔄 重试机制
    participant Circuit as ⚡ 熔断器
    participant Fallback as 🛡️ 降级服务

    Client->>Service: 发起请求
    Service->>Circuit: 检查状态
    Circuit-->>Service: 状态正常
    Service->>Service:执行业务逻辑
    Service-->>Circuit: 请求成功
    Circuit-->>Client: 返回结果

    Note over Client,Circuit: 故障发生
    Client->>Service: 发起请求
    Service->>Circuit: 检查状态
    Circuit-->>Service: 状态正常
    Service->>Service:执行业务逻辑
    Service-->>Circuit: 请求失败
    Circuit->>Retry: 触发重试
    Retry->>Service: 重试请求
    Service-->>Retry: 再次失败
    Retry->>Service: 再次重试
    Service-->>Retry: 仍然失败
    Retry-->>Circuit: 重试耗尽
    Circuit->>Fallback: 启用降级
    Fallback-->>Client: 返回降级结果

类依赖关系

classDiagram
    class CoreEngine {
        -moduleManager: ModuleManager
        -pluginManager: PluginManager
        -eventBus: EventBus
        +initialize()
        +analyze(source)
        +dispose()
    }

    class ModuleManager {
        -modules: Map~string, Module~
        -registry: ModuleRegistry
        +register(module)
        +unregister(name)
        +get(name)
        +list()
    }

    class PluginManager {
        -plugins: Map~string, Plugin~
        -loader: PluginLoader
        +load(pluginPath)
        +unload(name)
        +activate(name)
        +deactivate(name)
    }

    class ASTParser {
        -config: ParserConfig
        +parse(source): AST
        +traverse(node)
        +transform(ast)
    }

    class GraphDatabase {
        -nodes: Map
        -relations: Map
        +addNode(node)
        +addRelation(rel)
        +query(query)
        +getSubgraph(ids)
    }
